# K-water 경품추첨 웹 설계서

- 작성일: 2026-09-09
- 개발 환경: AntiGravity IDE + Codex
- 기술 구성: Next.js + Supabase + Vercel
- 운영 형태: 한 번에 하나의 행사만 운영하는 재사용형 웹
- 예상 규모: 행사당 101~500명

## 1. 목적

강연장 QR코드를 스캔한 참석자가 스마트폰으로 개인정보 수집·이용에 동의하고 경품에 응모할 수 있는 웹을 구축한다. 관리자는 응모 마감과 추첨을 통제하고, 강연장 화면에서는 확정된 당첨자를 경품별로 한 명씩 공개한다. 전체 공개 후 관리자가 결과를 공유하면 참석자 스마트폰이 자신의 당첨 또는 미당첨 결과 화면으로 자동 전환된다.

## 2. 확정된 운영 규칙

1. 경품 기본 구성은 스캔기기 10개, 텀블러 10개, 키보드 10개로 총 30개다.
2. 참석자는 한 사람당 최대 한 개의 경품만 받을 수 있다.
3. 참석자가 30명 미만이면 전원이 당첨되고 남는 경품은 미추첨 처리한다.
4. 참석자와 30개의 경품 슬롯을 각각 무작위로 섞은 뒤 앞에서부터 1:1로 연결한다.
5. 동일 연락처는 한 행사에 한 번만 응모할 수 있다.
6. 응모 마감 후 관리자가 별도의 `추첨 실행` 버튼을 눌러 전체 결과를 한 번에 확정한다.
7. 강연장 발표 순서는 스캔기기, 텀블러, 키보드다.
8. 엔터를 누를 때마다 이미 확정된 당첨자 한 명만 공개한다. 엔터 입력은 재추첨을 의미하지 않는다.
9. 강연장에는 당첨자의 성명 전체와 소속부서를 표시하고 연락처는 표시하지 않는다.
10. 부적격·불참 당첨자가 있으면 해당 당첨자만 제외하고 동일 경품의 대체 당첨자를 선정한다.
11. 전체 공개가 끝난 뒤 관리자가 `결과 공유`를 실행해야 참석자 스마트폰에 결과가 표시된다.
12. 결과 공유 시각으로부터 7일 후 개인정보와 개인별 추첨 결과를 자동 삭제한다.
13. 관리자와 강연장 화면은 행사 공용 비밀번호로 보호한다.

## 3. 시스템 구조

### 3.1 화면 주소

| 주소 | 대상 | 역할 |
|---|---|---|
| `/` | 참석자 | 행사 안내, 응모 폼, 대기, 개인 결과 |
| `/display` | 진행자 | QR코드, 실시간 응모 인원, 당첨자 순차 공개 |
| `/admin` | 관리자 | 행사 설정, 명단 관리, 마감, 추첨, 결과 공유 |

### 3.2 구성 요소

- Next.js는 세 화면과 서버 API를 제공한다.
- Vercel은 Next.js 애플리케이션을 공개 인터넷에 배포한다.
- Supabase Postgres는 행사, 경품, 참석자, 추첨 결과, 공개 상태, 작업 이력을 저장한다.
- 실시간 채널은 행사 상태 변경 사실만 참석자·강연장·관리자 화면에 알린다.
- 개인정보 등록, 추첨, 대체 추첨, 결과 공유, 삭제는 서버에서만 실행한다.
- Supabase 관리자 키, 개인정보 암호화 키, 공용 비밀번호는 Vercel 환경변수로 관리한다.

## 4. 행사 상태 모델

| 상태 | 의미 | 허용되는 다음 동작 |
|---|---|---|
| `SETUP` | 행사 준비 | 응모 시작 |
| `OPEN` | 응모 진행 | 응모 마감 |
| `CLOSED` | 응모 마감 | 응모 재개 또는 추첨 실행 |
| `DRAWN` | 결과 확정 | 강연장 공개 시작, 대체 추첨 |
| `REVEALING` | 강연장 순차 공개 | 다음 당첨자 공개, 대체 추첨 |
| `REVEALED` | 전체 공개 완료 | 결과 공유, 대체 추첨 |
| `PUBLISHED` | 개인 결과 공유 | 개인정보 즉시 삭제 또는 자동 삭제 대기 |
| `PURGED` | 개인정보 삭제 완료 | 다음 행사 설정 |

추첨 완료 후에는 응모 재개와 참석자 수정·삭제를 금지한다. 대체 추첨은 결과 공유 전까지만 허용한다. 결과 공유 후에는 당첨 결과를 변경할 수 없다.

## 5. 참석자 화면 설계

### 5.1 응모 화면

네이버 폼 캡처 `IMG_4893.png`, `IMG_4894.png`, `IMG_4895.png`의 모바일 카드형 구성을 시각적 참고자료로 사용한다. 네이버 로고와 네이버 고유 UI는 복제하지 않는다.

화면 구성은 다음과 같다.

1. 행사 안내 카드
   - 행사명
   - 주관부서와 강연 정보
   - 일시와 장소
   - 경품 추첨 안내
2. 참석자 성함 입력 카드
3. 연락처 입력 카드
4. 소속부서명 입력 카드
5. 개인정보 수집·이용 동의 카드
   - 수집 항목: 이름, 연락처, 부서
   - 이용 목적: 참석자 사전조회 및 이벤트 진행
   - 보유기간: 당첨 결과 발표 후 7일
   - 동의/미동의 선택
6. `경품 응모` 버튼

### 5.2 입력 검증

- 성명과 소속부서는 공백만 입력할 수 없다.
- 연락처는 하이픈과 공백을 제거한 숫자로 정규화한다.
- 휴대전화 형식이 아니면 구체적인 수정 안내를 표시한다.
- 개인정보 이용에 동의하지 않으면 응모 버튼을 활성화하지 않는다.
- 제출 중에는 버튼을 잠가 반복 클릭을 막는다.
- 데이터베이스의 행사별 연락처 해시 고유 제약으로 동시 중복 제출도 차단한다.

### 5.3 응모 완료와 결과

- 응모 성공 후 `응모가 완료되었습니다. 결과 발표를 기다려주세요.` 대기 화면으로 이동한다.
- 스마트폰 브라우저에는 개인정보가 아닌 임의의 개인 확인 토큰만 저장한다.
- 같은 브라우저로 다시 접속하면 대기 또는 결과 상태를 복원한다.
- 결과 공유 전에는 개인 당첨 여부를 반환하지 않는다.
- 결과 공유 시 실시간 알림을 받은 뒤 개인 토큰으로 자신의 결과만 조회한다.
- 당첨 화면에는 `행복해하는 방울이.png`와 `축하합니다! {경품명}에 당첨되셨습니다.`를 표시한다.
- 미당첨 화면에는 `슬퍼하는 방울이.png`와 `꽝!! 아쉽지만 다음 기회에!`를 표시한다.
- 두 방울이 이미지는 투명 배경 PNG를 그대로 사용하며 캐릭터를 변형하거나 자르지 않는다.

### 5.4 행사 상태별 화면

| 상태 | 미응모자 | 응모자 |
|---|---|---|
| `OPEN` | 응모 폼 | 응모 완료 대기 |
| `CLOSED` | 응모 마감 안내 | 대기 |
| `DRAWN`~`REVEALED` | 응모 마감 안내 | 대기 |
| `PUBLISHED` | 응모 마감 안내 | 개인 당첨·미당첨 결과 |
| `PURGED` | 종료된 행사 안내 | 종료된 행사 안내 |

## 6. 강연장 화면 설계

### 6.1 응모 단계

- 행사명과 큰 QR코드를 화면 중앙에 표시한다.
- QR코드는 운영 도메인의 참석자 주소를 가리킨다.
- 실시간 응모 인원을 함께 표시한다.
- 프로젝터용 16:9 화면을 기본으로 하며 브라우저 전체화면에서 잘리지 않아야 한다.

### 6.2 발표 단계

- 공용 비밀번호 인증이 완료된 화면에서만 엔터 입력을 처리한다.
- 추첨 전에는 `관리자가 추첨을 준비하고 있습니다.`를 표시한다.
- 추첨 후에는 `Enter를 눌러 발표를 시작하세요.`를 표시한다.
- 공개 순서는 스캔기기, 텀블러, 키보드로 고정한다.
- 엔터를 누를 때마다 한 명의 `성명 전체 · 소속부서`를 애니메이션과 함께 추가한다.
- 한 경품의 발표가 끝나면 다음 엔터에서 다음 경품으로 이동한다.
- 당첨자가 없는 경품은 자동으로 건너뛴다.
- 엔터를 길게 누르거나 빠르게 반복해도 한 번에 한 명만 공개되도록 입력 잠금을 적용한다.
- 현재 공개 위치를 서버에 저장해 새로고침 후에도 이어서 진행한다.
- 최종 화면에는 세 경품의 공개된 전체 명단을 경품별로 표시한다.

## 7. 관리자 화면 설계

### 7.1 인증

- 행사 공용 비밀번호를 입력해 로그인한다.
- 비밀번호 원문은 코드와 데이터베이스에 저장하지 않는다.
- 연속 실패 횟수를 제한하고 일정 시간 추가 시도를 차단한다.
- 인증 성공 후 `HttpOnly`, `Secure`, `SameSite` 속성이 적용된 관리자 세션을 발급한다.
- 관리자와 강연장 서버 API는 모든 요청에서 세션 권한을 재검증한다.

### 7.2 행사 설정

- 행사명, 일시, 장소, 안내 문구
- 개인정보 수집 항목, 이용 목적, 보유기간
- 경품명, 수량, 발표 순서
- 한 번에 하나의 행사만 활성화
- 이전 개인정보가 남아 있으면 다음 행사 시작 차단

### 7.3 운영 대시보드

- 현재 행사 상태
- 실시간 응모 인원
- 참석자 성명, 연락처, 소속부서
- 추첨 전 참석자 수정·삭제
- 응모 시작, 응모 마감, 추첨 전 응모 재개
- 추첨 실행과 최종 확인창
- 경품별 공개 진행률
- 대체 추첨
- 전체 공개 후 결과 공유
- 개인정보 삭제 예정일과 즉시 삭제
- 다음 행사를 위한 초기화

### 7.4 안전장치

- 모든 중요 동작은 현재 상태와 대상 인원을 서버에서 다시 확인한다.
- 추첨 실행 후 참석자 명단과 경품 구성을 잠근다.
- 전체 재추첨 기능은 제공하지 않는다.
- 공개 완료 전 결과 공유 버튼을 비활성화한다.
- 작업 이력에 동작, 시각, 사유, 변경 전후 대상을 기록한다.

## 8. 추첨 설계

### 8.1 최초 추첨

1. 행사 상태가 `CLOSED`인지 확인한다.
2. 추첨 실행에 대한 데이터베이스 잠금을 획득한다.
3. 유효 참석자 목록을 확정하고 안전한 서버 난수로 섞는다.
4. 설정된 수량만큼 경품 슬롯을 만들고 안전한 서버 난수로 섞는다.
5. 두 목록을 앞에서부터 `min(참석자 수, 경품 수)`만큼 연결한다.
6. 한 참석자당 하나의 결과만 저장되도록 고유 제약을 적용한다.
7. 경품별 당첨자 공개 순서를 다시 무작위로 정한다.
8. 결과와 공개 순서를 저장하고 행사 상태를 `DRAWN`으로 변경한다.
9. 같은 요청이 다시 들어오면 재추첨하지 않고 기존 결과를 반환한다.

### 8.2 대체 추첨

1. 관리자가 기존 당첨자와 제외 사유를 선택한다.
2. 기존 당첨자를 부적격 처리해 이후 모든 추첨에서 제외한다.
3. 미당첨·유효 참석자 중 한 명을 안전한 서버 난수로 선정한다.
4. 기존 당첨자와 동일한 경품을 배정한다.
5. 강연장 공개 목록과 공개 진행 상태를 일관되게 갱신한다.
6. 변경 전후 당첨자와 처리 사유를 작업 이력에 남긴다.
7. 후보가 없으면 경품을 미추첨 상태로 전환한다.

## 9. 데이터 구조

| 테이블 | 주요 책임 |
|---|---|
| `events` | 행사 설정, 상태, 결과 공유 시각, 삭제 예정일 |
| `prizes` | 경품명, 수량, 발표 순서 |
| `participants` | 암호화 개인정보, 연락처 해시, 동의 시각, 개인 토큰 해시 |
| `draw_results` | 참석자와 경품 연결, 공개 순서, 공개·제외 상태 |
| `reveal_state` | 현재 경품과 공개 위치 |
| `audit_logs` | 관리자 중요 동작과 대체 추첨 이력 |

행사별 연락처 해시는 고유해야 한다. 참석자와 추첨 결과는 행사 식별번호로 묶어 다른 행사 데이터와 섞이지 않게 한다.

## 10. 개인정보 및 보안

- 성명, 연락처, 소속부서는 서버에서 암호화한 뒤 저장한다.
- 정규화한 연락처는 비밀키 기반 해시로 변환해 중복 검사에만 사용한다.
- 개인 확인 토큰도 데이터베이스에는 해시로 저장한다.
- 브라우저가 Supabase 테이블을 직접 읽거나 수정하지 못하도록 접근 정책을 적용한다.
- 관리자 권한이 필요한 데이터와 동작은 서버 API를 통해서만 제공한다.
- 강연장 API는 공개 단계에 맞는 성명과 소속부서만 반환한다.
- 서버 로그, 분석 도구, 오류 추적 정보에 개인정보를 기록하지 않는다.
- 결과 공유 시각으로부터 7일이 지나면 만료 데이터를 즉시 조회 차단한다.
- 매일 자동 삭제 작업을 실행하고 실패 시 재시도와 관리자 경고를 제공한다.
- 삭제 대상은 개인정보, 개인 토큰, 개인별 결과, 개인정보가 포함된 작업 이력이다.
- 삭제 후 행사명, 총 응모자 수, 경품별 지급 수량 같은 비식별 통계만 유지할 수 있다.

## 11. 오류 및 복구

| 상황 | 처리 기준 |
|---|---|
| 제출 도중 응모 마감 | 저장하지 않고 마감 안내 표시 |
| 동일 연락처 동시 제출 | 데이터베이스에서 한 건만 승인 |
| 제출 중 네트워크 오류 | 재시도 안내와 등록 여부 확인 |
| 실시간 연결 끊김 | 자동 재연결과 주기적 상태 확인 병행 |
| 추첨 버튼 동시 호출 | 첫 요청만 실행하고 나머지는 기존 결과 반환 |
| 강연장 화면 새로고침 | 서버의 마지막 공개 위치 복원 |
| 엔터 키 반복 입력 | 짧은 입력 잠금으로 중복 공개 차단 |
| 결과 공유 전 개인 조회 | 대기 상태만 반환 |
| 대체 후보 없음 | 해당 경품 미추첨 처리 |
| 자동 삭제 지연 | 조회부터 차단하고 다음 작업에서 재삭제 |

## 12. 시각 디자인 기준

### 12.1 참석자 화면

- 모바일 우선 반응형 디자인을 사용한다.
- 밝은 회색 배경 위에 흰색 둥근 카드를 세로로 배치한다.
- 제목은 굵고 높은 대비로, 설명은 중간 회색으로 표시한다.
- 하늘색 계열을 항목 번호, 아이콘, 주요 버튼의 강조색으로 사용한다.
- 필수 항목과 오류는 빨간색으로 명확하게 표시한다.
- 입력창과 버튼은 한 손 조작이 편한 충분한 높이와 간격을 확보한다.
- 네이버 로고, 네이버 폼 문구, 네이버 고유 상표 요소는 사용하지 않는다.
- K-water 행사 서비스임을 알 수 있는 제목과 물방울 모티프를 적용한다.

### 12.2 결과 화면

- 방울이 이미지를 화면의 핵심 시각요소로 중앙 배치한다.
- 당첨 화면은 밝은 하늘색·노란색 포인트와 축하 분위기를 사용한다.
- 미당첨 화면은 차분한 하늘색 계열을 사용하되 지나치게 어둡거나 부정적으로 만들지 않는다.
- 당첨 경품명은 가장 큰 텍스트로 표시한다.
- 이미지의 투명 여백을 고려해 모바일에서 캐릭터가 잘리지 않도록 `object-fit: contain` 방식으로 표시한다.
